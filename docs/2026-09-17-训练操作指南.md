## 1. 环境准备（每个新终端只做一次）

```powershell
cd F:\GithubDeskClone\FloraQwen

# 方式 A（推荐）: 用项目自带启动器, 自动设环境变量 + 用 floraqwen 的 python
.\scripts\run.ps1 scripts\check_env.py

# 方式 B（手动）:
#   1) 设置模型缓存环境变量 (否则会去 C 盘重新下载 8.9GB 模型):
. .\scripts\set_env.ps1
#   2) 激活虚拟环境:
conda activate floraqwen
#   3) 检查环境 (torch/CUDA/依赖):
python scripts\check_env.py
```

验证环境后，先跑一次模型加载冒烟测试（约 40 秒），确认站点补丁仍然有效：

```powershell
python logs\smoke_load_model.py     # 期望输出 SMOKE TEST PASSED
```

> ⚠️ **重要**：本机 transformers 5.5.0 有一个手工站点补丁（Windows 下 safetensors 改用
> `pread` 后端，见工作记录 §4.4）。**任何 `pip install -U transformers` 或重装环境后，
> 补丁会丢失，必须重新验证**（冒烟测试会立刻暴露问题）。

## 2. 数据准备（数据已就绪，以下为完整重做流程）

```powershell
# 2.1 下载并整理 Flowers102 (~80 分钟, 已完成则跳过)
python scripts\download_flowers102.py --out data\raw\flowers102

# 2.2 生成训练标签 (官方 train 划分 1020 行; --all 生成全部 8189 行)

# 2.3 生成 ShareGPT 训练集
python scripts\prepare_data.py --labels data\raw\labels.csv --images-dir data\raw --out data\processed\train.json --max-per-class 3   # 子集 (每类 3 张, ~915 条)
python scripts\prepare_data.py --labels data\raw\labels.all.csv --images-dir data\raw --out data\processed\train.full.json            # 全量 (~24466 条)

# 2.4 构建评估集 (官方 test 划分, 硬链接零额外磁盘)
python scripts\build_test_set.py --max-per-class 20               # -> data\test (2040 张 / 102 类)
```

## 3. 训练

### 3.1 训练命令（子集与全量通用）

```powershell
# 子集试训练 (915 条, 174 步, 实测约 88 分钟):
python scripts\train_lora_trl.py --config configs\lora_config.yaml

# 全量训练 (24466 条): 通过 --data 参数切换数据, --out 换输出目录:
python scripts\train_lora_trl.py --config configs\lora_config.yaml `
    --data data\processed\train.full.json `
    --out models\lora-qwen3vl-4b-flora-full
```

> 说明：`train_lora_trl.py` 是 Windows 可用的 transformers+peft 后端（`train_lora.py` 依赖
> unsloth，本机未安装）。配置文件 `configs/lora_config.yaml` 中的 `data_path`/`output_dir`
> 会被 `--data`/`--out` 覆盖。

### 3.2 关键参数（configs/lora_config.yaml）

| 参数 | 值 | 说明 |
|---|---|---|
| 量化 | 4-bit NF4 + 双量化 | QLoRA，显存约 2.7GB（权重） |
| LoRA | r=16, alpha=32, dropout=0.05, 7 类线性层 | 可训练 ~40M 参数 |
| batch | 1 × 梯度累积 16 | 等效 batch 16，显存不变 |
| 学习率 | 1e-4，cosine，warmup 3% | |
| 视觉编码器 | 冻结 | 省显存且花草任务无需微调视觉塔 |
| 精度 | bf16 | 4060 支持 |

### 3.3 时长预估（本机实测单步 ~31 秒）

| 数据 | 样本数 | 步数/epoch | 3 epoch 总时长 |
|---|---|---|---|
| 子集（每类 3 张） | 915 | 58 | **~1.5 小时** ✅ 推荐先跑这个 |
| 官方 train 划分（每类 10 张） | 3081 | 193 | ~5 小时 |
| **全量 8189 张** | 24466 | 1530 | **~40 小时** ⚠️ 见下 |

### 3.4 全量训练的现实建议

全量 3 epoch ≈ 40 小时（单步 31 秒 × 4590 步）。可行的取舍：

1. **epochs=1**：全量 1 epoch ≈ 13 小时（改 `configs/lora_config.yaml` 的 `num_train_epochs: 1`，或临时复制一份配置）；
2. **官方 train 划分**（1020 张/类 10 张，3081 条，3 epoch ≈ 5 小时）——防泄漏且覆盖全部 102 类，是比"全部 8189 张"更规范的方案（test 的 6149 张本就该留作评估）；
3. 夜间/挂机跑，`save_steps` 已有检查点兜底（`models/.../checkpoint-100` 可单独用于推理验证）；
4. 提速方向（未验证）：升级 transformers（含上游修复后可去掉站点补丁）、换有原生 CUDA 内核的量化后端、或换更大显存机器。

## 5. 常见坑（全部来自本日实测）

1. **模型加载段错误**（加载 30% 处崩溃、无报错）：transformers 5.5.0 + Windows mmap 提交限额问题；站点补丁已修复，重装环境后必须重跑 `logs\smoke_load_model.py` 验证；
2. **标签顺序**：VGG 官网 `categories.html` 是**字母序**，`imagelabels.mat` 编号对应的是**官方原始顺序**（以 TFDS oxford_flowers102 为准）——按字母序直接编号映射会产生全盘错误的训练标签（2026-09-17 已修正）；
3. **视觉输入丢失**：训练数据的 `<image>` 占位必须转成 `{"type": "image"}` 消息内容块，否则 Qwen3-VL 看不到图（`train_lora_trl.py` 已修正并带 `logs\collator_test.py` 验证）；
4. **内存**：本机仅 15.6GB 内存且长期高占用，大任务前建议关闭浏览器等大户；
5. **旧 adapter**：`models/lora-qwen3vl-4b-flora` 为错误标签产物，推理无意义，请重训后使用。
